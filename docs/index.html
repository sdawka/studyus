Four planes, read top-down in invocation order. The two lower planes are libraries and services — never agents: folds and frontiers stay reproducible and cheap. Plane 3 · services now, agent tools later

Pedagogy engines

Four engines, not one function per pedagogy verb — a capability joins an existing engine as a mode when it shares that engine's reads and writes, and becomes a new engine only when its I/O contract differs. Each is a headless (userId, input, env) → output service: reads only via the Learner Profile facade, writes only events (named exceptions in the matrix below). Every mode carries its own status dot.

Session orchestrator — the coach

New

The conductor, with an assistant-coach personality: plans the arc, narrates why each step was chosen, prompts planning and reflection, and attributes struggle to strategy — never ability. The only engine that calls peers.

planopen the session: goal, time box, what's due and why
conductsequence engine calls; adapt the arc as evidence arrives
reflectclose with a recap, what unlocked, one metacognitive prompt

The event log, in full

The log widens from learning evidence only into the complete activity stream — everything the learner does lands here, but only evidence moves mastery. Role flags (is_instructional / is_assessment) already make the fold ignore context events arithmetically; the one new guard is that idle-decay's lastEventAt must read evidence events only, so checking off a task never fakes freshness.

Invariants the chart encodes

Events are the only writerNo pedagogy engine touches mastery columns; they append events and the fold re-derives. Exceptions are named in the matrix: lifecycle rows and generated items (exercise), conversations (instruction), tasks/sessions/notifications (admin).
Evidence moves mastery, context never doesThe full activity stream lives in one log, but only role-flagged evidence reaches the fold — and idle decay counts evidence events only.
Derived beats persistedFrontier, freshness, traversed overlays: computed at read. Only the event log and the misconception lifecycle earn persistence.
State math is never agenticPlanes 1–2 are deterministic libraries. LLMs live in Plane 3 and above, where nondeterminism is the point.
One read surfaceEngines read the Learner Profile facade, not raw tables — so the facade can evolve (caching, closure tables) without touching every caller.
The agent is a shellEvery engine ships as a service first; the per-learner agent adds session state and channel reach, never business logic.
Orchestrator calls peers, peers don'tOnly the orchestrator composes engines. Peer-to-peer calls are forbidden — keeps the call graph a star, not a web.
Modes before functionsA new capability joins an existing engine as a mode when it shares that engine's reads and writes; it becomes a new engine only when its I/O contract genuinely differs.
Coach, don't rescueEvery surface narrates why, prompts reflection, and attributes struggle to strategy — never ability. Scaffolds fade rather than take over; no guilt framing, ever.
