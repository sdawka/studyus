# ADR-003: D1 + Drizzle ORM

**Status**: Accepted

**Decision**: Use Cloudflare D1 (SQLite) with Drizzle ORM 0.45.2 for data persistence.

## Context

StudyBuddy needs a relational database for:
- User courses, branches, KCs.
- Event log (append-mostly, but editable).
- Assessments, grades, session history.
- Notes, tasks, resources.

Alternatives:
- **Neon (PostgreSQL)**: Better features, but adds external dependency; D1 is colocated.
- **Fauna**: Proprietary; less transparent query performance.
- **D1 + raw SQL**: Manual migration management; no type safety.
- **Prisma**: Type-safe, but heavier; Drizzle is lighter and more explicit.

## Decision

**Cloudflare D1 + Drizzle 0.45.2**:
- SQLite for simplicity; `wrangler d1 migrations apply`.
- Drizzle for type-safe queries, migration generation, and minimal runtime overhead.
- `migrations/` directory holds SQL files (generated by `drizzle-kit`).

## Consequences

**Positive:**
- D1 is colocated with Workers (no latency across regions).
- SQLite is lightweight, easy to snapshot/restore.
- Drizzle generates migrations; we manage schema in TypeScript.
- `db.batch()` gives us atomic multi-statement writes for mastery recompute.
- Local dev uses real D1 (not mocks), so test results match production.

**Negative:**
- SQLite has limits (no row-level security; full-table locking on writes).
- Drizzle 0.45 is stable but not 1.0 yet.
- Scaling beyond D1's limits requires migration (post-v1).

## Schema Management

1. Update `src/db/schema.ts`.
2. Run `drizzle-kit generate` → generates SQL in `migrations/`.
3. Commit migration files.
4. On deploy: `wrangler d1 migrations apply studybuddy --remote`.
5. On local dev: `wrangler d1 migrations apply studybuddy --local`.

## Notes

- **No foreign key constraints** in schema (D1/SQLite enforce at app level).
- **Indexing strategy** defined post-v1 (analyze query patterns first).
- **Mastery fold is pure**: queries are simple reads + single batch write.

See `docs/architecture/data-model.md` for schema.
